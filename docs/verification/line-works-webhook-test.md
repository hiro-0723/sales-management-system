# LINE WORKS Webhook初期検証手順

状態：設計時点の確認計画。実環境で確立後に結果と実際の操作へ更新する。

## 1. 対象

- テスト用LINE WORKS Bot
- 営業管理用Cloud Runサービス
- Cloud Tasksのテスト用キュー
- Apps Scriptテスト用Webアプリ
- テスト用Google Sheets
- 地域情報共有の1対1トーク

## 2. 実施前条件

- 本番とテストのBot、認証情報、デプロイ、保存先が分離されている。
- Bot Secretと内部共有秘密がSecret Manager等へ保存され、Gitやログへ含まれていない。
- Callback URLを設定する前に、署名検証単体テストが成功している。
- テスト利用者とダミーデータが決まっている。
- 作成・更新・削除対象と復元方法について許可を得ている。

## 2.1 ローカル自動テスト

```bash
node --test lineworks/apps-script/InternalApi.test.cjs
node --test lineworks/cloud-run/test/task-result.test.js
```

正常条件：

- Apps Script 6ケースがすべて成功する。
- Cloud Run 4ケースがすべて成功する。
- 署名不一致、期限切れ、重複、処理途中復旧、一時失敗を含む。
- Apps Script一時失敗はCloud RunでHTTP 503へ変換される。
- 恒久的な入力エラーはHTTP 200で完了し、無駄な再試行を行わない。

## 3. 署名検証

| ケース | 期待結果 |
|---|---|
| 正しいBot ID・署名・本文 | Cloud Tasksへ1件登録 |
| 署名不一致 | 拒否し、Cloud Tasksへ登録しない |
| Bot ID不一致 | 拒否し、Cloud Tasksへ登録しない |
| 本文改変 | 署名不一致として拒否 |
| JSON不正 | 業務処理へ渡さない |
| 未対応イベント | データ登録せず、安全な応答 |

秘密値とメッセージ本文全体をログへ出さない。

## 4. Callback応答

- 正常CallbackへHTTP 200を返す。
- Cloud Tasks登録後、Apps Script処理完了を待たずにLINE WORKSへ応答する。
- 連続送信時も後続イベントを不必要に待たせない。
- 受付失敗時の応答と再送挙動を確認する。

## 5. Cloud Tasks

| ケース | 期待結果 |
|---|---|
| 正常タスク | Cloud Runタスク処理を経由し、Apps Scriptへ1回登録される |
| Apps Script一時失敗 | 設定した範囲で再試行 |
| 永続的な入力エラー | 無制限再試行しない |
| 同じタスク名 | 短期重複として拒否 |
| 同じrequestIdの再配信 | Apps Script側で二重登録しない |

キューの最大配信速度と同時配信数を、Apps ScriptとSheetsの安全な範囲へ制限する。

Cloud Tasksの送信先はApps ScriptではなくCloud Run`/tasks/process`とする。Cloud Run IAM/OIDCで認証し、Apps ScriptのJSON結果が`retryable: true`の場合だけHTTP 503を返す。

## 6. Apps Script内部入口

| ケース | 期待結果 |
|---|---|
| 正しい内部署名・有効期限 | 入力検証へ進む |
| 内部署名不一致 | データを変更しない |
| 期限切れ | データを変更しない |
| requestId重複 | 既存結果を返し、再登録しない |
| 未登録利用者 | データを変更しない |
| 必須不足 | データを変更しない |
| 文字数超過 | データを変更しない |

## 7. 地域情報共有

正常条件：

- 1対1トークで入力を順番に案内できる。
- 登録前に確認内容を表示する。
- 「登録」後だけテスト用シートへ保存する。
- 地域情報IDが1件だけ発行される。
- 投稿者、部署、分類、内容、関連先が想定列へ入る。
- 管理列と既存営業予定変換の前提を壊さない。
- 利用者へ地域情報IDと登録完了を返す。

中断・異常条件：

- 「キャンセル」で会話状態を破棄する。
- 一定時間経過後は最初から案内する。
- 未登録利用者は業務入力へ進めない。
- 同じ送信を再処理しても2行作らない。

## 8. 既存経路の回帰確認

- Googleフォームから地域情報を登録できる。
- 地域情報共有（生データ）へ保存される。
- 地域情報共有シートへ転記される。
- 地域情報IDが発行される。
- 地域情報から営業予定へ変換できる。
- 既存の二重追加防止が動く。
- 営業ダッシュボードを更新できる。

LINE WORKS経路を追加してもGoogleフォーム経路の結果を変えない。

## 9. 復元

- テストで作成した地域情報、受付記録、会話状態を一覧化する。
- 許可された方法でテストデータを削除または初期状態へ戻す。
- 再読込後に対象データが復元されていることを確認する。
- 本番データに変更がないことを確認する。

## 10. 記録する根拠

- 対象リビジョン・Apps Scriptバージョン
- テスト日時
- ケース別の結果
- HTTPステータス
- requestIdと地域情報ID
- 秘密値を除いたログ
- LINE WORKS画面
- Sheets保存結果
- 復元後の状態
