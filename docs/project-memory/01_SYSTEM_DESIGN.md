# システム設計書

既存の「営業管理システム v1.0 設計書 Ver.4（20260701）」を正本とし、現在の開発判断に必要な内容だけを保持する。

## 1. プロジェクト概要

- プロジェクト名：営業管理システム
- 現行版：v1.0現場運用版
- 次期版：v2.0（LINE WORKS中心の入力UI）
- 主な利用者：営業担当、社員、ケアマネ、管理者、代表
- 目的：地域情報、営業予定、訪問履歴、紹介実績をつなぎ、計画的な営業活動と振り返りを支える。
- 現在の課題：Googleフォーム中心の入口は、約1か月の現場運用で使いづらさが確認された。

## 2. Mission

地域情報を営業行動へ変換し、営業担当が予定を宣言し、実行し、記録し、振り返って次の行動へつなげられる状態を作る。

## 3. Vision

会社全体の地域情報が営業活動へ循環し、どの情報が訪問、紹介、契約につながったかを追跡できる。

## 4. North Star

- 営業担当が「何となく営業する」のではなく、地域情報をもとに今日の予定を宣言する。
- 新機能は「宣言 → 実行 → 記録 → 振り返り」のどこを強くするかで判断する。
- 入力負担を増やさず、現場で毎日使えることを優先する。

## 5. 現在の完成範囲

v1.0では、次の流れが実機で正常動作したと利用者から確認されている。

- 営業予定フォームから生データ保存、1件1行展開、PlanID付与
- 営業報告リンクからPlanID付き報告、完了更新、訪問履歴ID書き戻し
- 地域情報フォームから生データ保存、管理シート転記、地域情報ID付与
- 地域情報から営業予定への変換、PlanID書き戻し、二重追加防止
- 営業ダッシュボード表示

約1か月の現場運用は完了している。Phase 1〜8は完了し、設計書上のPhase 9は未開始である。

## 6. v2.0の現在テーマ

Googleフォーム中心の入口を、次の構成へ移行する設計を開始する。

```text
LINE WORKS
  ↓
Webhook
  ↓
Google Apps Script
  ↓
既存の業務ロジックとGoogle Sheets
```

移行では入力UIと業務ロジックの境界を明確にし、既存データとID体系を保護する。

## 7. データ設計の原則

- 正式な業務データ保存先は既存Google Sheetsとする。変更は設計確認後に行う。
- `地域情報ID → PlanID → 訪問履歴ID → 紹介実績`の関係を維持する。
- 「営業予定（生データ）」と「地域情報共有（生データ）」はフォーム回答の保管庫であり、直接編集しない。
- 管理・営業予定化は管理用シートで行う。
- LINE WORKSからの入力を既存の生データ形式へ合わせるか、共通入力モデルを新設するかは未確定である。
- 移行時も既存データの上書きや一括変換を前提にしない。

## 8. 主要アーキテクチャと責務

- UI・設定層：`SalesPlan.js`、`RegionInfo.js`
- 営業予定処理：`SalesPlanEngine.js`
- 地域情報処理：`RegionInfoEngine.js`
- 営業報告・訪問履歴：`VisitReport.js`
- 閲覧・振り返り：`Dashboard.js`
- 初期設定：`SystemSetup.js`
- 診断：`Diagnostics.js`
- v2.0入力層：LINE WORKS Webhook用の専用モジュールを追加する方針。名称・API・認証方式は未確定。

## 9. 確定している移行方針

- v1.0の既存設計と業務データを壊さない。
- `SalesPlanEngine.js`、`RegionInfoEngine.js`、`Dashboard.js`などは可能な限り流用する。
- 主な変更対象は入力UIとその接続層とする。
- Googleフォームを直ちに削除せず、移行中のバックアップまたは並行確認経路として扱う。
- LINE WORKS連携の実装前に、入力、認証、エラー、再送、重複防止、権限、監査の仕様を決める。

## 10. 未確定事項

- LINE WORKS Botまたはアプリの具体的な利用方式
- Webhookの認証・署名検証方式
- 利用者識別と営業担当名の対応方法
- 営業予定、営業報告、地域情報共有の会話フロー
- Webhook再送時の冪等性キーと重複防止
- エラー時の利用者通知、管理者通知、再処理方法
- Googleフォームとの並行運用期間と終了条件
- Apps Script Webアプリのデプロイ構成と権限
- LINE WORKSへ送信してよい情報の範囲

未確定事項は、公式仕様と利用者判断を確認してから確定仕様へ移す。
